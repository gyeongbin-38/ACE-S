# EVOLUTION

Use when the next decision depends on independent deployment, schema/protocol compatibility, migration, rollout, reversibility, provider replacement, or long-horizon change.

Check first:
- what must evolve independently?
- which versions must coexist?
- what data/protocol migration order is safe?
- what choice creates lock-in?
- what staged reversal or migration path exists?
- what kill condition should reopen the decision?

Do not load for local reversible implementation details.

If material, read `../references/evolution-deployment.md`.
