# GENERIC Entry Manifest

This is an **entry mode, not a specialist domain**. It exists so an ACTIVE task is not forced into CODE, DOCUMENT, RESEARCH, or STATE when none clearly dominates yet.

## Use when

Context selection matters, but no specialized source structure clearly owns the next step.

Typical examples include:

- operational files/data whose processing method matters more than repository structure;
- working/session history that needs selective retention or handoff;
- mixed inputs where the next useful source or capability must be identified before specialization;
- tasks where a cheap inspection is needed to learn what kind of context is actually present.

## Do not use when

A specialized domain already clearly dominates the next retrieval:

- repository structure → CODE;
- a bounded long document set → DOCUMENT;
- external multi-source evidence → RESEARCH;
- controlling/current vs superseded/conflicting state → STATE.

Do not stay GENERIC merely to avoid making a clear specialized choice.

## Entry action

Identify **one concrete next context target or capability**. Prefer metadata/index-level inspection before loading content broadly.

Examples of useful questions:

- What source/artifact must be inspected next?
- Is an existing capability already sufficient to read/process it?
- Is the real problem retention of working history rather than source navigation?
- Did the bounded inspection reveal a known specialized domain?

Do not enumerate every possible file type, tool, or future route.

## Lazy additions

- capability/source access unknown → load `manifests/tools.md`;
- working history, handoff, or later-step utility → load `manifests/retention.md`;
- exact source truth/provenance matters → load `manifests/evidence.md`;
- date/version/freshness can change the answer → load `manifests/temporal.md`.

## Specialize only when earned

If a bounded inspection reveals that repository structure, a long document, external research, or conflicting state now dominates, switch to that one specialized manifest.

Do **not** fan out across all specialists to discover which one fits.

## Specialist policy

None by default. The purpose of GENERIC is to avoid loading an unnecessary specialist.
